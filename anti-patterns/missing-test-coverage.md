## 反模式说明

**问题**: PR 包含代码变更但缺少对应的测试

### 关键特征

- 新功能无单元测试
- Bug 修复无回归测试
- 重构无测试验证行为不变
- 测试文件变更为空或仅删除

### 为什么被拒绝

1. **质量保证缺失**: 无法验证代码正确性
2. **回归风险高**: 未来变更可能破坏现有功能
3. **维护成本增加**: 缺少测试的代码更难维护
4. **社区标准**: 大多数活跃项目要求测试覆盖

### 如何避免

1. **新功能**: 必须包含单元测试
   - 核心逻辑测试
   - 边界条件测试
   - 错误处理测试
2. **Bug 修复**: 必须包含回归测试
   - 复现 bug 的测试用例
   - 验证修复后的正确行为
3. **重构**: 必须确保现有测试通过
   - 运行完整测试套件
   - 补充缺失的测试
4. **测试质量**:
   - 测试应该独立、可重复
   - 避免测试间依赖
   - 使用清晰的测试命名

### 测试清单

- [ ] 新功能有单元测试
- [ ] Bug 修复有回归测试
- [ ] 测试覆盖核心逻辑
- [ ] 测试覆盖边界条件
- [ ] 测试覆盖错误处理
- [ ] 所有测试通过
